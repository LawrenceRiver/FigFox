# Paired evidence and local transactions

Compare the whole source and actual draft render first, then the paired regions. Record each confirmed discrepancy with a stable issue ID, region, independent `source_evidence`, `initial_evidence`, draft bounds and a concrete proposed correction. Record uncertainty separately. When a crop cuts an object, consult the whole image before calling it missing.

Check visible labels and formulas, object/row counts, graph topology, complete connector paths, head/body agreement, arrow ownership, relative geometry, overlap/containment, colors and typography. A path in the SVG does not establish a visible continuous arrow. Ignore harmless antialiasing differences; state the actual content or readability impact of a proposed repair. Do not correct a strange but readable source label from expectation.

Verify observations in the pixels before binding them to IDs. Each transaction names the allowed existing targets, dependencies and exact operations. A selected group includes its descendants. Include every insertion parent and every existing element to remove. If moving an object affects a connector, include that connector and its endpoint update. Resolve dependency order before execution. No issue may silently disappear: keep applied edits and unresolved reasons distinct.

After applying edits, render again and inspect the affected region plus neighbors. If an observation or transaction was wrong, retain the earlier record and correct its disposition; successful execution is not a repair pass. Same-assistant phases are sequential review passes, not independent agents or human validation.

For the editing probe, select actual IDs from `inspect`, create a copy-only transaction that changes one native text literal and one shape/group property or position, and moves a photo if one exists. Render and observe the intended differences. Record the executed operations, and verify the final deliverable hash did not change. Do not use a hidden probe to claim every possible editing operation is supported.

Source basis: [paired observation](https://github.com/LawrenceRiver/FigFox/blob/main/prompts/factual/g1.md), [verified targeting](https://github.com/LawrenceRiver/FigFox/blob/main/prompts/factual/g2.md), and the repository's factual native-operation contracts. Provider identities in the API runner are not requirements of the skill.
