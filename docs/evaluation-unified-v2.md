# Unified FigFox v2 evaluation

Authoritative source: user-supplied **FigFox_评分标准_v2**, registry SHA256 `78dce9c07e3096c1297afda583bade75c36bbac471c012bc8a17ea9fb8e799cd`. The older VisualScore-10 draft is historical, not used for this comparison.

The fixed comparison contains 80 matched original figures and seven candidate methods: FigFox S0C0/S0C1/S1C0/S1C1, AFE, Crafter and DrawAI. Generation outputs are immutable. AFE original `figure.png` is never substituted for its candidate render; final SVG is rendered with an isolated non-JavaScript renderer, and malformed or unsupported SVGs remain explicit failures/unknowns. Some AFE originals were resampled before generation; source-identity diagnostics and that input difference are reported separately, not used as a quality score.

## What v2 measures

Eighteen criteria cover content, relationships/structure, readability, editability, material fidelity and chart/data properties. The package reports pass/fail/unknown/NA, evidence coverage, critical failures and usability status. It does not define a numerical utility total or authorize a 10-point conversion.

A verified semantic inventory, actual editing evidence and software operation records cannot be generated by setting flags in model JSON. We therefore preserve two separate layers:

1. **Strict rule results** produced by the supplied unmodified package. Missing human-signed inventories and actual editing/round-trip evidence remain unknown. Model outputs are imported only into `model_reviews` with `verification=unverified`.
2. **Blinded model screening** using two isolated DeepSeek requests per renderable candidate, the same registry and prompts, the canonical source and candidate full views plus fixed overlapping quadrant views. Each Dxx has one whole-image screening slot. These slots are not an exhaustive semantic-unit inventory; model pass/fail proportions are advisory distributions, not verified quality scores or measured semantic coverage. Missing/invalid findings remain explicitly unassessed, never fabricated or silently retried.

No method labels, historical vendor scores, generation repair reports or other judge output are supplied to a judge. Method-identifying document content cannot be made literally invisible, so this is input-label blinding rather than a claim of perfect identity blinding. Two requests to the same model measure repeated-judge agreement, not independent human replication or bias removal.

D13/D14/D16 cannot be passed without actual selection/edit/save/reopen evidence. D17 has no automatically verified material pairing and D18 has no verified underlying numeric data; no missing evidence becomes NA or a measured pass. A parser can confirm malformed SVG, but successful XML parsing is only a structural proxy.

## Reporting

Ablation and vendor tables keep an 80-source denominator, item-level model distributions, inter-request agreement, invalid/missing outputs, rule statuses and unknowns. The main vendor comparison uses FigFox S1C1 and the same three external methods; the other three FigFox conditions stay visible in the ablation table. Any formal all-criteria usable result still requires the evidence demanded by v2. File availability, model screening and human verification are separate columns.

Assessment request IDs, actual responses, input/source/artifact hashes, token usage and configured-rate cost estimates are retained locally. Evaluation is separately tracked from generation. Historic generation failures and unknown-charge reserves are not reset. The previously authorized condition budgets remain enforced; vendor assessment expenditure uses an explicitly labeled administrative shared allocation, not a claim about vendor generation costs.
