# SP/TP 观察到参数的核对规则

这些是通用方法，不含测试图答案。

1. 先按原图记录对象种类、数量、主面及深度边方向，再选构造器。不要把说明书示例坐标复制成答案。
2. cuboid 的 origin 是主面左上角；u/v 是主面边。depth 是从主面角点走到后方对应角点的向量。屏幕向左为 dx<0，向上为 dy<0。看到左侧面时，通常深度朝左，不要因为示例朝右就填正 dx。确认实际可见面后，给该面的 colors 键：left/right 不是可互换的名称。
3. 阵列分别数 rows/cols；step_x/step_y 是相邻成员原点的差。不要把成员宽度、空白边缘间距、原点步进混为一谈；两行间距必须独立观察，不能默认等于列间距。
4. 从箭头起点到尖端依次追踪全部线段，列出每次转向，最后才选 line/polyline/rounded/cubic。不要跳过紧邻公式或文字的短横段。radius 只描述转角，不能补回漏掉的线段。
5. 文字 x/y 是基线；公式 x/y 是整个公式视口左上角，不是根号底边。保留根号横线及上下标，并根据参考整体定位。
6. 关系必须有可見证据：左边对齐意味着两条左边确实同 x；底边对齐意味着同 y。若只是“箭头在文字旁边”，不要编成 align_bottom。无法准确表达时保留具体描述为未知关系，不能用一个错误的已知关系凑数。
7. 输出前自查 kind 是对象类型，data.shape 才是几何构造器。逐个核对方向、计数、相邻距离、全部拐点，以及关系是否与自己给出的坐标一致。

本地 inspect_relations 会报告关系所需的世界位移；大位移表示参数与声明不一致，不能当成代码应该无条件纠正的依据。检查通过也不意味着与参考图一致。
