# Current-render observations and detector draft checks

The local build writes a new inputs/analysis directory only. It repaints the exact current SVG and requires exact RGBA and size agreement with the supplied current PNG before using measurements. Its text-hidden SVG/PNG are analysis copies, never candidate repairs. The unchanged native document.parse/measure callback owns both renders. No source/original PNG, model API or semantic inference enters the builder. Unsupported inputs/repaint mismatch preserve diagnostic artifacts and block usable proposals. Explicit coverage limits and uncapped observations are not a completeness claim.

The immutable V4 manifest activates semantic proposal_reviews. The host validates it and supplies proposals.json only to the initial semantic slot. Main retains the original native duties/report. Planner/verifier receive their ordinary current evidence; proposals do not persist as stale repair permission. All analysis artifact bytes, observation helper, detector parser and this document are frozen before actors begin; build timing (including native renders) is separately recorded in inputs/observation-build-timing.json and provenance. Timing is local overhead, not API timing.

Each proposal has a stable neutral ID, kind, actual current target IDs, bbox, observations/evidence, requires_source_verification:true and not_a_finding:true. Suggested frames only aid viewing. Probe families are low/no visible text ink, text-mask overlap groups, close text boxes, numeric frequency-unit casing, and continuous orthogonal open paths. Every probe requires independent source/current PNG and actual SVG examination. Original faint decoration, harmless contacts, ambiguous unit spelling and source-supported paths can be qualified. Neither kind, current coordinates nor nearby IDs prove meaning or edit authority.

`text_mask_overlap_group` retains every connected group of at least two eligible native text IDs using the same positive box-overlap relation that excludes ambiguous per-node text-mask attribution. Membership and IDs are deterministic; target_ids contain only these existing text members, bbox encloses them, and observations.member_boxes retain their native boxes. The original per-node `overlapping_text_mask_attribution` exclusion remains. A group is an unattributed current-render observation conditional on hiding all eligible text, never an individual member's intrinsic contrast or a source comparison.

The existing current and all-text-hidden arrays provide white-composited visibleRGB deltas and linear-sRGB relative-luminance contrast. Changed pixels are counted once within the union of rasterized member boxes (floor left/top, ceil right/bottom), excluding enclosing-rectangle corners outside that union. Inline facts retain changed pixel count, contrast p10/p50/p90 and fraction with contrast <=2.0, computed over all measured pixels. The existing 2.0 value remains an observation setting. All groups/members and aggregate facts remain present regardless of high, mixed or low statistics.

Every group always projects component detail to `ink_component_count` plus `component_evidence` artifact/name/hash/key/projection-note metadata in proposals.json. No component arrays or component bounds/coordinates are embedded, including for a one-component or empty group. All unassigned eight-connected component rows (current-PNG bounds, pixel count and p90) remain without size filters, truncation or top-k selection in the analysis-local `text-group-components.json`, keyed by stable proposal ID with revision/input/status bindings. This full artifact is written before proposals.json, hash-bound in both proposal/manifest artifact maps and frozen by the existing generic analysis inventory. Detail size/memory/time may grow with pixel-component count, while the model packet keeps a fixed set of per-group metadata fields plus all native member boxes; numeric count representation may widen. There is no total packet-size guarantee as group/member counts grow.

The full component artifact is offline audit evidence and unavailable to this role. Do not follow its reference or request/read the file: semantic allowed inputs remain proposals.json and the ordinary source/current/pack views. Omitted detail is neither passed nor negative evidence, and supplied source/current figures still determine necessity. Tiny antialias components remain in the audit; joins can merge unrelated ink and antialiasing can split it. Pixel components never become SVG member bindings. High aggregate or component p90 cannot certify absence of faint members. This projection adds no image input, render, tool/API call or semantic stage.

No conditional difference, including possible full nontext occlusion, yields `unknown_no_conditional_difference`, changed/component counts zero, null distribution statistics and an empty audit component list; this cannot establish an absent/invisible node or passed readability. Unsupported CSS masking dependencies or nonuniform pixel mapping retain the group with `measurement_status:unsupported`, explicit reasons and null measurements/component count/audit component list. Existing geometry/effect/paint eligibility and global repaint/dimension/input-hash guards remain in force; excluded nodes are not invented as group members. Hidden/revealed layers, blending, unsupported geometry/style/paint and white-flattened native exports limit attribution and cannot recover original alpha or other display backgrounds.

Review SOURCE+CURRENT independently under the existing necessity policy for necessary readable content. Overlap or low group/component statistics alone never requires a defect. Qualify harmless stacking, source-supported decoration or tiny details with actual source/current evidence and necessity reasoning. Preserve unresolved uncertainty through a complete uncertain native issue with actual current native bindings and the existing proposal-review partition. Neither component bounds, group IDs nor group membership grants edit permission, certifies repair completeness or establishes passed coverage.

When the manifest is present, semantic JSON must include proposal_reviews:[{proposal_id,decision:'required'|'uncertain'|'qualified',issue_ids,source_evidence,current_evidence,necessity_reason}]. Every known proposal occurs exactly once. All three evidence/reason strings are nonempty. Links are raw issue IDs reported in this same semantic response, before controller namespacing. Required links nonempty confirmed native issues; uncertain links at least one uncertain native issue, preserving unresolved knowledge in the ordinary active uncertainty queue; qualified has no links. Native issue objects retain description, original_evidence, current_evidence, existing current target/neighbor IDs or a real missing-content container, native image/category/decision rules. A proposal ID cannot become a finding ID or editable target. Missing description is rejected; reason is never an alias. Missing proposals do not certify coverage. Fixtures without a manifest retain the baseline schema.

Main and semantic may each call flow.py check-report RUN ROLE ABSOLUTE_OWN_DRAFT_PATH at most twice in the same dispatched slot. Drafts must resolve beneath that run's jobs/ROLE directory; foreign paths, symlink escapes and relative paths are rejected. Checks snapshot exact draft bytes (including invalid JSON), SHA, current state/revision, dispatch identity and result under detection/ROLE/report-checks/N. The shared parser checks exact revision/evidence/regions, current IDs, category profile, issues and programs:[] in both checks and final merge. Missing declared coverage remains explicit. Checks never render, execute programs, call providers, mutate state/queues or consume repair attempts. No check is available after final raw exists. Final receive freezes exact raw bytes and receipt before parsing, including malformed JSON; final resubmission is forbidden.

Analysis repaint and text-hidden mask images are local forensic artifacts, not model image inputs. Do not view them as source, before or candidate evidence. The semantic slot receives only proposal JSON and this contract alongside its ordinary actual source/current/crop evidence; the host manifest activates and validates the contract. An immutable observation-preparation-start marker or any analysis directory activates V4 mode. Missing/unsupported/inconsistent manifest, proposal status, input hashes or artifact hashes block begin and semantic checks; partial builds never fall back to the legacy schema.

An uncertain proposal review always links at least one complete uncertain native issue with the existing source/current evidence, category and actual current SVG bindings. An unlinked uncertain review is rejected. A harmless or source-unrequired detail may instead be qualified with source/current evidence and necessity reasoning. This preserves unknown knowledge without confirming a probe as a defect, granting edit authority or adding an observation lifecycle.

The local check executes no model/provider call itself. In a real provider tool loop, receiving check feedback may require additional HTTP turns; model role-slot count is not an API-request count. Measure actual API calls, usage and latency from transport/provider evidence. No zero-API test establishes real tool-loop API counts or timing.

Actual V4 preparation records its immutable preparation-start marker immediately after creating inputs, before reading runtime/catalog data, binding tools, copying assets or rendering the initial snapshot. An interruption at any later point cannot turn the checkout into a legacy fixture. The proposal-building helper does not recreate or move this marker; only explicitly legacy synthetic fixtures with no actual V4 preparation remain compatible without it.
