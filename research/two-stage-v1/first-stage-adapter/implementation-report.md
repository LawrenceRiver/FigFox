## Binding and commit boundary

`insertion_guard.bind/rights` use accepted normalized programs linked to the raw, still-unlowered tracked issues. Insertion anchors come only from explicit empty-target missing findings; existing-target write exceptions come only from separately linked explicit targets. Missing current IDs, root-SVG scope, duplicate IDs/issues, and ambiguous exact generated-source bindings fail closed. Aliased names do not become authority: the exact raw ID must still exist. Root anchors are conservatively unsupported in both arms, consistent with the native generated whole-SVG scope rejection.

`Flow.execute` installs `insertion_guard.transactions` around the real native `execute_programs`, then requires `verify(result)`. The context wraps the native module's `run_code`: original sandbox runs first, then its exact generated XML is proved before it returns to native code. It also wraps `write_checkpoint`: the identical proof executes for generated **and module** missing-content transactions immediately before native rendering/checkpoint creation, including any convergence changes. Failures raise within native's existing per-program try/rollback scope. Wrappers restore in `finally`; there are no native edits. `prompt_hashes` binds the new guard module.

For each program, current input file identity is checked and updated only after a successful native checkpoint. A source that matches more than one accepted generated program is ambiguous and rejected. Postproof logs bind exact before/output and normalized-program/source-code hashes. The common guard receipt is fsynced before the checkpoint call, records pass/failure and permitted scope, and is attached to successful result records. Success without a matching postguard receipt or receipt file fails closed. Sandbox failures without output have null output hash and an explicit failed receipt. There is no retry or model call.

## XML proof

Protected existing nodes retain tag, attributes, text, tail, parent and sibling order, recursively including anonymous descendants. Each insertion is rooted in a fresh-ID subtree attached directly to an exact explicit existing anchor; every ID in that subtree must be fresh and globally unique. Descendant anchors do not inherit insertion rights. Existing authorized subtrees may change only at their original location with root tag/ID and surrounding tail retained; other existing IDs cannot be borrowed into them. All protected IDs must survive.

New global styles, defs/resources, scripts, foreign/active elements, event handlers and active attribute schemes are prohibited; new content is restricted to ordinary SVG geometry/text/image groups. Global style/resource XML remains invariant even within separately writable target subtrees. Parser declarations/comments/processing instructions are conservatively rejected rather than silently discarded. Native SVG/sandbox/generated-raster/target-scope/capability/dependency/neighbor checks still run. This is an XML rights proof, not a claim of visual correctness or absence of occlusion; existing independent verifier duties remain.

## Supported-context extension after R3

R3 accepted the narrow guard but identified valid-SVG coverage exclusions. That subset is not represented as adequate for real SAM-on work. The blanket href/functional-paint/style rejection is now replaced by `dependency_proof`, an explicit local-reference and small static-CSS grammar. This extension is separately reviewable in `supported-context-boundary.md`; prior R1/R2/R3 review/proof artifacts are preserved.

The proof builds affected IDs from insertion-anchor and separately authorized target subtrees plus their ancestors. Preexisting local fragment hrefs and `url(#id)` references reject if they bind any fresh output ID (including previously dangling targets) or any affected ID; unchanged references to unrelated immutable resources are admitted. Protected unchanged `image` PNG data-URI hrefs have no document fragment binding and are admitted. Resource XML invariance and the ban on separately writable resource-bearing subtrees remain.

Literal rgb/rgba/hsl/hsla with numeric values are supported. Stylesheets may contain only static class, ID, type/universal or compound selectors and whitespace descendant combinations, comma lists, and an explicit SVG presentation-property set; declarations are static literals, the supported color functions, or checked local URLs. Structural/positional/pseudo/sibling/child selectors, at-rules, escapes, dynamic variables/functions, external/unknown references, unknown CSS and active SVG contexts still fail closed. Existing styles must remain byte-equivalent XML and cannot be inserted or edited. No browser/CSS engine or universal paint-equivalence claim is made.

`tdd-red-real-context.log` demonstrates the valid fixture was rejected before the extension. Actual native + actual macOS sandbox tests now successfully add missing neutral geometry in both code assignments to a fixture containing an existing embedded PNG, `.class`/`#id`/type/descendant CSS, rgb/rgba and an unaffected referenced gradient. Both-policy old dangling-href/URL capture and structural-CSS regressions still fail/roll back. New dependency tests reject affected anchor/descendant/ancestor refs, preserve static CSS coverage, and exercise functional-color and reference boundaries. All previous adversarial tests remain.
