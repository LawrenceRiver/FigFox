# 下一位同学如何接入

## 1. 固定任务和参考

先复制 `examples/input.json`。将 `synthetic` 改为 false，填写唯一 task_id、task_type、source、最终展示尺寸和目标软件。reconstruction 以原图及经裁决的人工参考为准；method_generation 以方法文本和内容计划为准。遇原图与方法矛盾，设 `source_conflict=true`，相关内容保持待裁决，图级返回 pending_reference。程序不会自行读方法并裁决。

建立人工参考单元，按 D01-D18 声明适用性与预期单元。D02 无公式、D17 无原生像素素材、D18 无图表可 NA；缺材料不能 NA。其它项仅任务明确豁免才能 NA；D03、D05 等与现有参考明显冲突的 NA 会被拒绝。人工参考不能只列容易验证的局部，应列全体目标。

## 2. 建立清单和映射

reference/candidate.objects 是语义对象清单，不要求 SVG 内存在 ID。id 可来自旁路标注，如“左侧第二个编码模块”；在 evidence 中提供实际渲染位置或软件选中记录。kind 可用 text/formula/shape/connector/table/image/chart 等。identity 是经裁决身份，count 是明确计数目标，bbox 使用同一图内的统一坐标系，parent 为直接父对象。

`matches` 为对象的一对一映射；重复对象各有独立 ID，缺失对象不硬配。`edge_matches` 为确认是同一语义连接的一对一映射，允许两边 ID 不同；连接方向错误也应保持此身份映射，确保同一根因只计一次。未显式匹配的边按已匹配端点构成多重图逐条核对，平行边保留重数。无法确定同一身份的遗漏与额外边先分别记录，人工确认同根因后再统一 root_cause。

附上 candidate.file 和 candidate.render（相对输入 JSON 所在目录，也可绝对路径）。可解析 SVG 只是结构代理，不能证明渲染正确。正式请求必须提供模型可见的真实渲染图片，如 PNG；示例中的 SVG 仅离线协议夹具，适配器不能假定每家 provider 支持 SVG 图片。不得执行候选脚本来生成预览；使用隔离、安全渲染工具，由接入方负责。

只有人工确认清单、bbox、关系和映射全部准确，才填写 semantic_evidence.source=human、verified=true 和 refs。该签认必须能回溯实际材料；人只点“同意模型结论”不构成操作证据。

## 3. 使用规则与证据

执行 evaluate 得到规则结果。D01 只对已签认且完全一致的转录给通过，不同字符串保留语义核实；D03/04/05/07 核对身份、数量、方向和归属；D08 仅对 id=bbox_layout 的声明单元比较匹配边界框的相对布局，其它布局关系保留待核实，不能覆盖所有对称/共边/科学比例语义。容差须在评图前按用途设置，示例 0.01 不是推荐阈值或校准标准。D13 按类型统计真实修改证据；D15 仅自动确认已签认的整页栅格化失败；D16 只做有限解析，完整通过需要操作链。

D17 现在支持可选的固定局部 MAE/MSE；D18 支持已核实显式数据与元数据核对，接入字段详见《局部图像与图表数值接入》。两项都不从原图自动提取语义或数据，也不因局部一致自动通过整项。其它项以及规则覆盖不到的部分，由模型或人工核实。不要把 bbox 测量当作全图视觉判断。规则 pass 仅限记录的测量范围；不能据此扩张为全部视觉性质通过。

编辑证据在 edit_evidence 中逐对象填写，必须改变实际内容，选择/移动截图不足以证明文本能改字。D16 的 operation_evidence 记录指定软件及版本、打开/修改/保存/重开/保持内容的全过程；任何步骤未发生不能写 true。程序不操控编辑软件，也不验证视频真实性。来源为 model/mock 的证据不成为 verified 事实。

## 4. 对接真实评判器（尚未实现）

`python3 -m figfox_score prepare ...` 生成 provider 无关请求包，其中有 system、18 条 item prompts、final_review、输入、原图、方法文本及候选附件的路径/存在性/SHA256 和响应 schema。请求包不上传任何文件，也不编码为某个 provider 的图片消息。

实现 `figfox_score.adapters.JudgeAdapter.judge(request) -> dict`。你的适配器负责：

1. 确认附件可读，将真正的渲染图片按 provider 规范编码和附加；缺附件不要发出虚假完整请求。
2. 将 system.md 作为系统约束；每项专用提示词与该项适用单元、参考及候选证据一同发送。终审使用 final_review.md，并附前述分项结果。
3. 将响应转换为 schemas/model-response.schema.json，保持 task_id、item_id、unit_id。source=model；不要生成 verified 字段。
4. 调用 validate_response(response,input)。格式、枚举、未知 ID、重复 finding、无证据 pass/fail 或多余字段均会拒绝。
5. 调用 merge_response 或 CLI import-response。模型结果进入 model_reviews 作为未验证建议，不直接改变规则事实、覆盖率或可用结论。JSON 合规不等于语义正确。
6. 人工审核建议及原始证据后，逐条将确认结果写入 input.evidence，source=human、verified=true，再 evaluate。若与已验证规则事实冲突，保留失败并标 conflict，回查清单/匹配或人工证据，纠正根因后重跑。不能用均分或模型“通过”覆盖关键失败。

本包没有真实 provider、网络客户端、重试策略、API key 管理或付费调用，也没有目标软件自动化。MockAdapter 只返回 unknown 并标 mock。实际生产中还需实现 provider 附件限制、预算、错误重试及审计记录，这些属于下一步接入工作。

## 5. 接入验收

先跑全部离线测试，再用人工已知答案的小样本核对真实渲染和目标软件操作。分别统计事实准确性、证据覆盖、未知率与评委一致性；本包未声称任何实测一致性或校准阈值。确认重数、逆向、数量、容器、整页位图和保存重开等反例均能被发现，再接主流程。接入前保持本包独立，不修改历史实验。

## 安全边界

离线运行不联网，不执行 SVG/方法文本/提示材料中的指令，不执行候选 JS，不跟随远程资源。SVG 解析限 10 MiB，DOCTYPE/ENTITY 拒绝；含脚本/foreignObject/事件属性仅报告代理线索，绝不运行。解析器仅检查 XML 可解析与 SVG 根，不验证 SVG 标准合规、资源完整、恶意链接或真实渲染；候选文件权限和路径访问由调用方控制。非 SVG 返回 unsupported_format/unknown，不把未知当坏文件。模型提示词防注入属于行为约束，不能替代隔离执行环境。
