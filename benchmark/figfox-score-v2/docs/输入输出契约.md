# 输入、输出和汇总契约

机器契约见 schemas/*.schema.json；运行时实施本包使用的 JSON Schema 子集（type/enum/properties/required/additionalProperties/items/minItems/maxItems/minLength/minimum/exclusiveMinimum）及跨字段约束。不宣称实现任意 JSON Schema。strict_json 额外拒绝重复 JSON key 和 NaN/Infinity。

## 输入

| 字段 | 约定 |
| --- | --- |
| version/task_id/synthetic | 版本 2.0、任务标识、是否合成数据；合成标记保留到结果 |
| task_type | reconstruction 或 method_generation，明确参考权威 |
| source | image 路径、method_text 路径可空；content_plan 与 reference_note 必填。内容计划也作为待评材料 |
| source_conflict | 原图与方法矛盾未裁决时为 true，图级 pending_reference |
| reference | objects 与 edges 完整人工参考清单；对象含身份、类型、父容器、计数、bbox、编辑要求、原生位图标记和 critical |
| candidate | 同样语义清单，加 file/render、output_confirmed_missing、whole_page_bitmap；confirmed_missing 必须确已确认未生成 |
| matches/edge_matches | 一对一对象/连接语义映射；ID 独立于 SVG；未匹配对象或边保留，不用 set 吞掉重复 |
| semantic_evidence | source、verified、refs；只有 human + verified + 非空 refs 才启用已核实语义规则 |
| display | width、height、unit(px/mm)、software；实际尺寸由评委查渲染，不由文件存在性推断 |
| tolerances | normalized_bbox 非负，事先设定；无通用默认合格阈值 |
| applicability | 必须包含 D01-D18；state=applicable/na/unknown，reason 必填；applicable 必须列预期 units，每个含 id/ref_ids/critical |
| evidence | 人工、模型或 mock 单元记录；模型不可自证 verified；已审人工记录可补充未知单元 |
| edit_evidence | 对象 ID、来源、verified、changed_actual_content、success、非空操作证据定位 |
| operation_evidence | 软件、版本、来源、verified、opened/modified/saved/reopened/preserved 及证据；静态图不能自动填 true |

每个清单内对象/边 ID 唯一，父对象存在且无环，边端点存在，bbox 宽高为正、数值有限。清单不完整、语义对应未经审核时应使用 unknown 或未验证证据，而非宣称已核实。

## 统一记录

每个 item 有 item_id、title、status、units、metrics、applicability_reason、coverage 与 distribution（NA 项没有 distribution）。每个单元有 item_id/unit_id、status、score、evidence、reason、primary_category、related_categories、severity、repair_scope、root_cause、source、verification、coverage、applicability；失败补 issue_id。score 固定 null：当前执行事实型 pass/fail 和 unknown，不引入未经校准的 0-4 等级。未来若引入语境等级，必须另定义锚点，不能与修复范围混合或把序数均值解释为精确效用。

状态：pass=该单元已验证范围达标，fail=已定位失败，unknown=待核实，na=本任务无此性质。verification 为 verified/unverified/proxy/conflict/synthetic_mock；来源为 rule/model/human/mock。proxies 是有限结构检查；model_reviews 是模型建议，二者不会自动补齐证据。

问题主分类取固定顺序中首次发现的条目；关联分类引用同一 issue_id。严重性 none/minor/major/critical 与修复范围 none/local/object/relation/global/unknown 独立。修复范围无法从实际操作推断时不估计时间或次数。自动规则对非关键违例保守给 major；实际人工应按科学影响细化。同根因多单元合并，不重复固定扣分。明确 edge_matches 的反向边只记一个错误；身份不明的未匹配缺失与额外边不武断认作同一根因。

## 真实测量

1. 对象：对已签认映射统计正确身份 C、遗漏 M、额外 E、身份错误 W。连接：以多重图统计 C/M/E/W；显式匹配但反向记 W，不再同时记一条 M 和 E。无需推测“整图相似度”。
2. 相对几何：每组 bbox 的原点减去集合最小 x/y，再除以集合总宽与总高的最大值 s（等比归一化）。单对象偏差 δ=max(|x_ref-x_cand|,|y_ref-y_cand|,|w_ref-w_cand|,|h_ref-h_cand|)，比较任务事先声明的容差。允许整体平移与等比缩放；不允许用 x/y 独立缩放抹去有意义比例。只在匹配参考完整时给测量结论，缺对象时保留 unknown。该测量只覆盖 bbox 布局，内部对称、共边、透视仍待语义核实。
3. 分类型可编辑比例：已验证成功修改实际内容的对象数 / 该类型应编辑对象数。没有操作证据记未覆盖，不假定可编辑；原生素材豁免不进分母。
4. 单项覆盖率：已判 pass/fail 的适用单元数 / 所有适用预期单元数（包括显式额外对象/边）。NA 不进分母；unknown 进分母。图级覆盖率将单元数合计，不能称为图质量分。未列单元的 applicability=unknown 项以项目状态阻止 usable，但不虚构单元数，因此同时报告 item_status_counts。
5. 分项汇总：任一 fail 则该项 fail；无 fail 但有 unknown 或缺预期单元则 unknown；全适用单元 pass 才 pass。统计分布与 coverage，绝不算序数均值。

## 图级结论及优先级

- pending_reference：源图/方法待裁决，优先于其它图级标签；失败仍保留明细。
- unusable：至少一个 critical 失败，不能被其它项通过抵消。
- needs_revision：存在非 critical 失败。
- pending_verification：没有失败，但仍有 unknown 项。
- usable：所有适用项均达标且无待裁决。

若既有失败又有未知，needs_revision/unusable 表示已经发现问题，不表示剩余性质已全部评完，应同时看 coverage。D16 文件确认缺失或损坏为 critical；未收到文件、格式不支持、权限或目标软件环境缺失为 unknown。模型建议与规则事实冲突不能直接擦除关键失败：保留失败，标 conflict，人工修正证据或清单后重跑。

## 模型响应

顶层 task_id、source=model/mock、findings。finding 必须是输入既有 unit_id；包含 item_id、status、evidence、reason、severity、repair_scope、root_cause。任务 NA 由输入决定，模型不得擅自返回 NA。无证据 pass/fail、额外字段（包括 verified 和 score）、重复 finding、错 task_id 或未知单元全部拒绝。当前语义定位字符串由接入方验证真实性，程序不解析视频内容，不检查证据真实性。

## 2026-10-15 条件数值扩展（仍属 D17/D18）

新增可选字段 `local_images={enabled,comparisons}` 与 `chart_checks=[...]`，不改变18项顺序，不要求旧输入补字段。两者均严格校验，measurement unit_id 必须属于对应适用单元，不允许用新字段覆写适用性。详细输入与公式见《局部图像与图表数值接入》。

结果仍遵循 result.schema.json：D17 的 `metrics.local_images[unit_id]` 记录 disabled/unknown/computed、computed、原因和实际测量；D18 的 `metrics.chart_data[unit_id]` 记录 data_status、完整对应标记、逐点误差、元数据错误和证据。局部测量/显式数据比较不自动把整项置 pass，故不能单独补齐视觉覆盖率；D18 明确失败会形成该单元 fail 和 issue。真实渲染仍待核实。
