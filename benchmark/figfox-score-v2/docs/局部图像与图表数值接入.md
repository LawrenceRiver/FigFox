# D17 局部图像测量与 D18 显式数据核对

2026-10-15 补齐；不新增评分项，不接模型 API。完整可运行输入见 examples/measurements-input.json 和 measurements-error-input.json。下列附加字段均可省略，旧输入继续有效。所有数值例子仅为合成测试，不是校准阈值。

## D17：固定素材、固定局部、固定变换

为 D17 声明一个适用 unit_id（示例 photo）。顶层 local_images.enabled 默认为未提供/关闭；comparisons 为局部对照数组，每个单元最多一条测量，含：

```json
{
  "unit_id": "photo",
  "asset_id": "native-1",
  "identity_evidence": {"source":"human","verified":true,"refs":["身份和区域对应的真实签认定位"]},
  "reference_file":"assets/reference.png",
  "candidate_file":"assets/candidate.png",
  "reference_region":[2,3,8,8],
  "candidate_region":[12,13,8,8],
  "transform":{"scale":1,"translation":[10,10],"allow_translation":true,"allow_uniform_scale":true}
}
```

region 为图像存储像素坐标的 [x,y,width,height]，左上包含、右下不包含，必须是非负整数且宽高为正。asset_id 是稳定素材身份；人工 refs 必须核实两区域确实是同一原生像素素材的对应局部。该证据不是程序自动识别身份，不能用相似外观替代。source=model/mock 的材料不启用已验证身份测量。

映射严格为 candidate_x = scale × reference_x + tx，candidate_y = scale × reference_y + ty；两个宽高也必须同时乘同一 scale。必须事先明确允许平移/等比缩放；禁止非等比变形、旋转、透视、任意重采样参数及搜索最优区域。变换与整数区域不一致或越界拒绝输入，不偷偷裁边、移位或拉伸。固定浮点计算一致性检查为 1e-9 绝对误差，仅用于变换数值表达，不是质量阈值。

仅支持单帧 PNG/JPEG。核心包不导入 Pillow；启用时按需加载。缺 Pillow 返回 state=unknown、computed=false、reason=optional_dependency_Pillow_missing；关闭时 state=disabled，不打开图片。不支持格式、丢失材料、图片不可读、EXIF 非默认方向或安全尺寸超限返回 unknown 原因，不推断质量失败。文件限32 MiB、解码图像限1600万像素、参考测量区域限400万像素；边界验证需要成功解码。

计算步骤固定并写入结果：

1. 校验两区域与已声明的均匀变换，按给定坐标裁切，绝不搜索。
2. 转为8位 RGBA，在白底上合成 alpha，再转 RGB；使用存储通道值，不做 ICC/gamma、亮度、对比度或颜色拟合。
3. 若候选区域网格与参考不同，仅把候选按固定双线性插值重采样到参考网格。这是已声明等比变换的局部网格对照，不允许独立 x/y 缩放。
4. 对 N 个 RGB 通道值计算 MAE = Σ|r-c|/(255N)，MSE = Σ(r-c)²/(255²N)，范围0到1。记录 ROI、transform、两个网格大小、处理方式、文件 SHA256 和身份依据。

数值只辅助模型/人工检查局部内容、裁切和科学关键细节。没有通用通过阈值，MSE=0 也不自动通过 D17；它不能证明素材身份签认真实或裁切范围正确。整图不计算主质量分。颜色管理差异、JPEG 压缩和重采样本身会影响指标，应结合用途解释。

## D18：显式数据与元数据比较

为 D18 声明适用 unit_id（示例 chart）。顶层 chart_checks 是数组，每条含：

- unit_id 与 evidence={source,verified,refs}，签认数据、系列身份、点对应和元数据真实。
- reference、candidate：各自含 axes.x / axes.y（scale、unit）和 series。任一数据对象可为 null，表示未提供底层数据，不是失败。
- series：每条有 id、semantic_id、legend_key、points；每个 point 有独立 id、数值 x/y。series/point ID 不必两边同名。
- series_matches：每条 ref、candidate 明确对应序列，并含 point_matches 的 ref/candidate 数组，不能猜测对应或自动排序、插值。
- tolerances.x_abs、y_abs：任务事先声明的非负绝对容差，沿给定单位解释，不自动换单位。边界值等于容差算一致；按输入数值十进制字符串计算差值，避免二进制浮点导致容差边界误罚。

简化数据对象示意（完整输入见 examples）：

```json
{
  "axes":{"x":{"scale":"linear","unit":"s"},"y":{"scale":"linear","unit":"m"}},
  "series":[{"id":"s1","semantic_id":"distance","legend_key":"Distance",
    "points":[{"id":"p0","x":0,"y":1},{"id":"p1","x":1,"y":2}]}]
}
```

代码逐项比较轴 scale/unit 与对应序列 semantic_id/legend_key。明确不一致即记录错误；单位或尺度不一致时不继续把数值当同一量作比较。只有身份和坐标含义一致，才按已声明点对应比较 |reference-candidate| 与容差。重复 ID、非有限数、负容差、非一对一或指向不存在对象的映射拒绝。未提供数据、未签认、没有点或映射不完整给 data_status=unknown；已经能定位的明确错误仍给 fail，不因为其它部分未知而掩盖。

数据与元数据全部对齐且完整对应时，metrics.chart_data[unit_id].data_status=pass；整项 D18 仍为 unknown，因为程序没有证明候选图实际绘制了这些点、刻度或趋势。数值/轴/单位/图例错误使该 D18 单元 fail，证据引用参考、候选及 errors 中具体位置。严重性采用任务该单元的 critical 标记或默认 major，修复范围 object；不以数值大小自动猜科学严重性。

若图表有更多轴、单位换算、不同采样、百分比语义或特殊变换，应由接入方建立清楚契约后另行扩展；本实现不会猜测或从像素读取数值。视觉核实继续使用 D18 专用提示词和真实渲染证据。

## 复现和预期

在 Pillow 可用的 Python 环境、交接目录中执行：

```sh
python3 -m figfox_score evaluate examples/measurements-input.json --out examples/results/measurements.json
python3 -m figfox_score evaluate examples/measurements-error-input.json --out examples/results/measurements-error.json
python3 -m figfox_score prepare examples/measurements-input.json --out examples/results/measurements-request.json
```

一致夹具：原始局部从 (2,3) 平移至 (12,13)，固定8×8局部 MAE/MSE 均为0；图表 data_status=pass；D17/D18 都待视觉核实，图级 pending_verification。变动夹具：一个局部像素变动使误差大于0；y=2 改成2.1，超过显式容差0.01，D18 fail，并因该合成单元标记 critical 而图级 unusable。

无 Pillow 的环境同样可运行；D17 显示未计算的明确原因，D18 数值核对正常进行。PNG/JPEG 由合成程序生成，所有身份与数据签认只是测试夹具事实，不冒充真实人工操作或真实用户评分。实际接入请替换为可追溯证据。
