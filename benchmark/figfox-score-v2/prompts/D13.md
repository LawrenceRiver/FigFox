# D13 内容可编辑
必须与 system.md 同时使用。请求中的 input、attachments、applicability 是本次待评材料。

检查目标：文字、公式、形状、连线和表格能够修改其实际内容。
评价单元：一个应编辑的语义对象，按类型汇总。一次 finding 只评价请求里一个 unit_id；多个单元分别给记录，不能用“多条关键边错误”描述一条边的分数。
证据要求：真实选择/修改前后、保存重开证据及对象定位。核对 input.reference 与 candidate 的语义对应，在候选渲染指明位置；证据不足返回 unknown 并说明缺什么。
允许差异：软件原生等价表示及合适公式编辑方式。
失败边界：字形路径冒充文字、整页贴图、不能改变内容。
专用反例：SVG 中有 path 但文字不能改字。
代码与模型职责：代码按类型统计已验证编辑证据；模型审核操作记录与语义对象对应。规则产出的结构代理不等于语义或软件行为已验证。
不适用处理：完整参考确认没有此类单元时为 NA；不能因评委缺材料而标 NA。 不自行更改请求的适用性；若认为适用性错误，返回 unknown 并说明，交给人工修订输入。

判定步骤：
1. 确认 unit_id、ref_ids、语义映射和证据覆盖；不能定位就 unknown。
2. 核对该单元全部目标，先排除上述合理差异，再逐一寻找可定位失败边界。
3. 有明确违例给 fail；覆盖充分且全部达标给 pass；部分未核实给 unknown。事实核对不要用字符串相似率替代语义判断。
4. fail 的严重性按科学含义与使用影响单独判断；修复范围按局部/对象/关系/全图单独描述；同根因使用同一 root_cause。

结构化响应：顶层 {"task_id":"请求原值","source":"model","findings":[...]}。
每个 finding 必须有 item_id="D13"、unit_id、status（pass/fail/unknown）、evidence（证据定位字符串数组）、reason、severity、repair_scope、root_cause。不得增加字段。pass 时 severity=none、repair_scope=none；unknown 时说明未验证部分。此响应仅是模型建议，不能自证为真实验证。

编辑专项：核实指定软件、版本、对象定位、修改内容、保存和重开后的记录。静态截图最多证明可见状态；实际操作链缺失时编辑能力保持 unknown。
